How to Use ​

In the conventional 2D, 3D, and Lite presets, enable scripting as follows:

  1. Set Page to Scripting.
  2. Turn Script Enabled on.
  3. Enter a Lua script into Script Text, or use Paste Script to paste it from the clipboard.

In the Mug Typography Scripting preset, the Scripting group appears directly on the Global page, so no page switch is required. This preset omits Character Settings and Part Settings, supports up to 512 characters and 1,024 parts, and controls individual characters and parts from Lua. Use a conventional preset when you want to combine individual Inspector editing with Lua.

For example, this script alone keeps every character swaying with a per-character phase offset:

lua
function OnLayout(ctx)
    for index, character in mt.each_char(ctx) do
        character.rotation = math.sin(ctx.time * 2.0 + index * 0.4) * 15.0
        character.offset_y = math.sin(ctx.time * 3.0 + index * 0.7) * 0.02
    end
end

The script overrides the inspector values every frame, so it combines freely with keyframes and other features such as deformers, Write On, and 3D.

For static layouts or decoration that do not depend on time, -- @time_independent lets the plugin skip Lua execution and text rendering on unchanged frames. Do not add it to the example above, which animates with ctx.time. See Time Independence and Render Reuse for the conditions and a static example.

The Four Callbacks ​

A script can define up to four functions. All of them are optional.

CallbackTimingTypical use
OnInitialize(ctx)Once when the script loadsPrecompute constants stored in chunk-scope local variables
OnPreLayout(ctx)Before layout, every frameChange base values: text, tracking, alignment, global colors, camera
OnLayout(ctx)After layout, every frameAdjust position, rotation, scale, and colors per character and part
OnPath(ctx)After OnLayout, every frameSelect only needed parts through ctx.paths and replace their outlines with normalized SVG-compatible paths or Bézier curves

When a rendered overlay is reused, these callbacks are not evaluated for that frame.

The core model is two-staged: first the base values are settled, then the characters and parts generated from that base are adjusted. Changes that affect the character count (such as a typewriter effect) belong in OnPreLayout; moving individual characters belongs in OnLayout.

The mt.* namespace provides target iteration through mt.each_char / mt.each_part, numeric utilities such as mt.clamp / mt.lerp / mt.remap, easing in mt.ease.*, color helpers in mt.color.*, time control in mt.timeline.*, and mt.svg_path for reusable SVG-compatible paths.

The VSCode Simulator (MT Sim) ​

The distribution ZIP includes the VSCode extension Mug Typography Scripting Simulator (MT Sim) in the scripting-simulator/ folder. It lets you develop and preview scripts entirely without launching the host application.

  • Install: In the VSCode Extensions view, choose "Install from VSIX..." and select the bundled .vsix file.
  • Launch: Open a .lua file and run Mug Typography Scripting Simulator from the preview icon in the editor title or from the Command Palette. Saving the file reloads it instantly.
  • Copy to the plugin: Click Copy Script in the top toolbar, then click Paste Script in the plugin to replace Script Text.
  • Editing support: Completion and hover documentation for ctx.* and mt.*, filtered so each callback only offers the fields it can actually write.
  • Scene reproduction: Timeline playback, font selection, per-character and per-part inspectors, an evaluated-values view, and a camera preview for the 3D presets.

API level and plugin compatibility

To use every feature, use the latest plugin. Samples and scripts that use newer APIs do not run on an older plugin. The current plugin is API Level 12.

Use the VSCode extension together with the plugin from the same distribution ZIP.

The online simulator supports the latest API, so it shows a notice asking you to update the plugin, and keeps showing it until you confirm that you have.

The simulator is an approximate preview

MT Sim approximates the plugin's layout and rendering. Gradient interpolation, projected stroke quality, and similar details are simplified, so always verify the final result in Mug Typography itself.

Try it in your browser ​

No installation required: an online simulator ↗ is also available directly in your browser. It offers the same editing support and sample collection as the VSCode extension, making it a convenient way to try things out or learn the API.

Publishing your work to the gallery ​

Animations you make can be published to the online simulator's gallery. Published work appears under the sample browser's Community section, where anyone can open a card to read the script or use it as a starting point for their own.

Submissions are taken on the gallery repository ↗, which Submit to Gallery in the simulator's menu also opens. Its README covers what to attach and how.

Having an AI Write the Script ​

You do not need to know Lua. Describe the motion you want to a chat assistant such as ChatGPT or Claude and it can write the script for you. Because these assistants do not know Mug Typography, you must give them the AI-oriented API reference first. Skip that step and you will get scripts that call functions which do not exist, or that get units and directions wrong.

Steps ​

  1. Load the reference. Start a new chat, attach the file below from the distribution ZIP, and ask the assistant to read it.

    text
    scripting-simulator/docs/lua_api_for_ai.md

    If your assistant cannot take attachments, open the file in a text editor and paste its full contents instead. Assistants that can fetch web pages can be given the URL below, though many cannot, so attaching is the safer default.

    text
    https://mug-lab-3.github.io/mug-typography-docs/lua_api_for_ai.md

  2. Check that it was read. The reference is a large file, and some assistants quietly skip large attachments. Ask this next:

    What are the arguments of mt.stagger, including their units?

    If the answer is time (seconds), index (1-based), delay (seconds) and duration (seconds), the reference was read correctly. If not, see If it does not work.

  3. Describe the animation you want. The more specific you are, the closer the result will be.

    Make the letters bounce up one by one from below, then have the whole line sway gently once they have all appeared.

    For an effect that will never use 3D controls, explicitly ask for a 2D-only script or say limit it to 2D. A compatible assistant will add the script setting that selects the 2D rendering path even in the 3D-capable Scripting preset. Skipping 3D projection can improve rendering speed, but it also disables every 3D Inspector setting and keyframe, including Camera and Global 3D controls. Do not request 2D-only output if you may add 3D motion later.

  4. Copy the returned code into Script Text, or load it with Paste Script.

  5. If the motion is not what you wanted, just say so. You can keep refining with follow-ups like "make the bounce stronger" or "drop the swaying".

If it does not work ​

A failed check in step 2, calls to functions that do not exist, units or directions that are clearly wrong — all mean the reference was not read. Try these in order.

  1. Start a new chat and attach it again. Long conversations drift away from what was attached first; asking right after loading the reference is the most reliable.
  2. Paste the full text instead of attaching it. Open the reference in a text editor, select all, and paste it into the chat. This is read more reliably than an attachment.
  3. Try a different assistant. Small models running on your own machine often cannot take a reference this large.

Use the simulator to check the result

The host cannot show you script error details. Paste the script into MT Sim or the online simulator and you get the error message and line number, which you can hand straight back to the assistant to have it fixed.

Mug Typography MCP (preview) ​

This is a preview

Mug Typography MCP is a preview. Its features and behavior may change without notice.

Mug Typography MCP is an MCP server that explains Mug Typography's features, Inspector parameters and Lua scripting API to AI clients such as Claude and Codex. Instead of attaching the reference in step 1, the assistant reads what it needs from the MCP.

  • Specification: provides the plugin's features, the Inspector parameters, the Lua scripting API and the bundled samples to the assistant.
  • Font names: lists the fonts the plugin can select, so a font can be chosen by its display name.
  • Script checking: runs the Lua script the assistant wrote in the simulator and checks errors, characters that leave the screen, value changes and a one-frame preview image before handing it over.

It does not operate DaVinci Resolve itself. To let the assistant also add nodes and set the Script Text, the AI client needs a DaVinci Resolve MCP as well. The preview image is only a guide to placement; always check the result in DaVinci Resolve.

Requirements

  • Windows 11 (64-bit), or macOS 13.3 or later (Apple Silicon only)
  • DaVinci Resolve Studio 21.1 or later with Mug Typography installed
  • One of these AI clients: Claude Desktop, Codex, Cursor, VS Code (GitHub Copilot), Gemini CLI, Antigravity

How to use

  1. Run the installer (Windows: MugTypographyMCP-Setup.exe, macOS: MugTypographyMCP.pkg). It installs for the current user only and registers itself with the AI clients it finds.

  2. Restart the AI client, or reload its MCP servers.

  3. Ask the assistant for the effect you want.

    On the current clip, add a Mug Typography effect where the letters of "HELLO" drop in one by one from above.

You can check or remove the registration from the Start menu's "Mug Typography MCP" on Windows, or from MugTypographyMCP in ~/Applications on macOS. Check the connection in that window shows what the assistant sends and what comes back.

On macOS the downloaded installer may be reported as unverified. Open "System Settings > Privacy & Security", scroll down, and press "Open Anyway" next to MugTypographyMCP.pkg.

Samples and API Reference ​

The distribution ZIP ships many ready-to-use Lua samples in scripting-simulator/samples/:

  • reference/ — short, numbered lessons for the scripting model and API
  • showcase/ — finished animation patterns: typewriter, bounce-in, neon glow, 3D camera moves, and more
  • diagnostics/ — internal scripts for verifying the environment and API behavior

Follow reference in numeric order: 01–11 teach callbacks, characters, parts, inheritance, and layout fundamentals; 12 onward covers the mt.* utilities by purpose. APIs whose behavior depends on option combinations switch between those configurations inside one comparison script.

The sample browser has a category and genre navigation tree beside the sample list. Showcase starts with Everyday animations. Select a sample name to inspect its full description, then choose Open in editor to load it. Search covers all genres, including Japanese and English genre names and API names used by bundled scripts. Play preview runs reference and showcase samples inside the browser. Controls inside the preview let you pause, seek, or enter fullscreen without changing the script or scene being edited. Click the preview to play or pause. Controls fade out when the pointer leaves, remain visible during keyboard navigation, and toggle on a screen tap during touch playback. Community previews use posted images and videos, loaded on demand. Navigation and search remain selected when the browser is reopened. Shared sample URLs and saved scenes use the original sample paths.

The online simulator's sample browser shows only content intended to be read and adapted: reference, showcase, and gallery. To verify that Scripting is working, run Scripting Check from the menu. It reports the result without changing the script or scene currently being edited.

For the complete specification, see the Lua Scripting API Reference. The same reference is also included for offline use under scripting-simulator/docs/ in the distribution ZIP.

For parameter details and limitations, see Scripting Settings.
