Target API level: 6

ctx is the context that Mug Typography passes to each callback. It contains the information needed to process the current frame, including the current time, canvas information, Global settings, and the generated characters and parts.

The available fields and write permissions differ by callback. This document first lists availability for each callback, then describes the fields of ctx in order. For the callback execution order and purposes, see Callback Overview.

1. List of ctx Fields ​

The fields directly under ctx are themselves read-only and cannot be replaced with other values. However, objects such as ctx.global and ctx.chars[index] contain fields that can be modified depending on the callback. ○ indicates that a field can be read in that callback.

1.1 ctx.time / ctx.frame / ctx.fps ​

These fields express the current evaluation position relative to the beginning of the clip. ctx.time is in seconds, and ctx.frame is in frames. Because ctx.frame can include subframes, it is not necessarily an integer. ctx.fps is the number of frames per 1 second.

1.3 ctx.fonts ​

A read-only, 1-based array containing the names of installed fonts recognized by the host. Its contents match the Font list in the host UI, and in OnPreLayout its elements can be assigned to ctx.global.font_name.

Neither the array elements nor the number of elements can be changed.

1.4 ctx.timeline ​

FieldTypeUnitDescription
availableboolean—Whether a finite clip range could be obtained
start_frame / end_framenumberframeStart/end of the range (clip-local; the start is always 0)
duration_framesnumberframeend_frame - start_frame
duration_secondsnumbersecondDuration converted to seconds
progressnumber0–1Current position clamped to 0–1

Clip Range ​

The clip range is the clip's actual range on the timeline, including trimming and extensions before or after it. ctx.time, ctx.frame, and ctx.timeline receive values on the same time axis, with the beginning of the clip as 0. When applied to a video clip as a filter, they also follow that clip's range.

When available is false, the other values are 0, so provide a fallback.

NOTE

Limitation of extending the beginning in generator use: When the beginning of a generator clip (with no input connected) is extended on the timeline, the host treats that interval as a still image of the first frame, so script time does not advance until the extension boundary (the intro appears frozen in its initial state). To change the duration, change the length of the generator clip itself instead of extending it. This limitation does not apply when used as a filter.

Time-Axis Design Rules (Anchor × Speed) ​

Animation timing is designed along 2 axes: "① where it is fixed (anchor)" and "② how fast it advances (speed)." The default speed is real seconds (based on ctx.time), and progress, which scales proportionally with clip length, should be used only for the "full-span" pattern described below.

PatternAnchorHow to Write It
Intro (entrance)Beginning of clipUse ctx.time directly (real seconds). For a combined intro + outro, use mt.timeline.intro_outro_seconds (§10.9)
Outro (exit)End of clipmt.timeline.remaining(ctx) (real seconds remaining until the end; §10.9)
Typewriter, stagger, spring, etc.Beginning of clipctx.time (real seconds; specify a physical speed such as ◯ seconds per 1 character)
Full-span pattern (drift, sweep, or reveal across the entire duration)Entire clipprogress (the expected behavior is for the movement to lengthen when the duration is extended)

If a transition is written as a fraction of progress, extending the clip makes the fade or typing run in slow motion and breaks the intended behavior. An outro is fundamentally about aligning with the end rather than making its speed proportional to the duration, so write it in real seconds anchored to the end.

lua
-- NG: typing speed changes when the clip length changes
local visible = math.floor(mt.timeline.progress(ctx) * ctx.char_count)

-- OK: constant 0.08s per character regardless of clip length
local visible = math.floor(ctx.time / 0.08)

-- OK: outro fade over the last 0.5s, anchored to the clip end
local fade = mt.clamp(mt.timeline.remaining(ctx) / 0.5, 0.0, 1.0)

-- OK: 0.8s intro + 0.5s outro at fixed real-time speed
-- (compressed automatically only when the clip is shorter)
local intro, outro = mt.timeline.intro_outro_seconds(ctx, 0.8, 0.5)

1.5 ctx.font — Metrics for the Font in Use ​

Metrics (dimensional information) for the font in use, resolved after layout generation.

FieldTypeUnitDescription
ascentnumbercanvas height ratioAscent upward from the baseline
descentnumbercanvas height ratioDescent downward from the baseline (positive value, expressed as a downward amount)
line_heightnumbercanvas height ratioLine height
units_per_emnumberfont design unitNumber of design units in the font's em square

NOTE

The final on-screen size can be predicted from the product of scale-related fields (2D presets only). The host internally calculates font size as a fixed ratio of canvas.height, so the same ratio is preserved even when the canvas resolution changes. For 2D presets, multiplying this base size by character.scale × character.stretch_x/y, part.scale, and ctx.global.scale × ctx.global.stretch_x/y gives the actual on-screen size (because all of these transformations are composed multiplicatively).

For 3D presets, this product is only an approximation. Camera projection performs perspective division according to depth (including z, apparent depth changes caused by yaw/pitch, and the camera's perspective / zoom), so on-screen size changes nonlinearly with depth, and a tilted character is distorted differently at each vertex and cannot be represented by a single scale factor. ctx.font and character.geometry contain pre-projection values, and the post-projection on-screen size cannot be obtained from OnLayout.

1.6 ctx.text / ctx.char_count / ctx.part_count ​

ctx.text is deprecated. Use ctx.global.text to read the current text, and assign to ctx.global.text in OnPreLayout to rewrite it.

ctx.char_count and ctx.part_count are the number of valid characters and parts, respectively, after layout generation. When the text or font changes, these values also change according to the shaping result.

ctx.global.margins ​

Indexing and Calculation ​

margins is a 1-based array keyed by character number in layout order. This number is the same as the index later assigned in ctx.chars. margins[i] is added in em units, together with tracking, to the advance after the i-th character.

text
(margins[i] + tracking) * designUnitsPerEm
Array Format ​

It must be a numeric-keyed array without holes from 1 through #margins. Non-integer keys, string keys, holes in the middle, and non-number elements cause an error.

The default number of elements is ctx.meta.limits.max_characters. When assigning an entire table, a shorter dense array than the default number of elements can also be used. Elements beyond the character count do not cause an error; they are simply unused.

Character Count ​

ctx.char_count is undefined in OnPreLayout. utf8.len(ctx.global.text) returns the number of UTF-8 code points, which may differ from the number of characters after shaping because of combining marks, ligatures, grapheme clusters, and similar constructs. Perform operations requiring the exact count in OnLayout.

Merging Subobjects ​

Assigning an entire table, as in ctx.global.shadow = { enabled = true, distance = 8.0 }, performs a per-field merge. Omitted fields retain their current values.

ctx.global.fill ​

NOTE

The color Type

color is a table with r (red), g (green), b (blue), and a (alpha). Each field is a number from 0–1; a = 0 means fully transparent, and a = 1 means fully opaque.

Fields can be assigned directly. When assigning an entire table, you can specify only the fields to change. Omitted fields retain their current values.

lua
ctx.global.fill.color.r = 1.0
ctx.global.fill.color = { a = 0.5 }

Fields other than r / g / b / a, and values other than numbers, cause an error.

colorcolorRGBA 0–1Global fill color. Also serves as the gradient start color
transparentboolean—When true, hides the fill while preserving strokes and effects

Characters whose chars[index].fill.use is false use fill.color. For the inheritance order including parts, see "Inheritance Mechanism".

ctx.global.shadow ​

NOTE

This shadow has no blur/softness whatsoever. It is a solid-color copy with sharp outlines, using the same shape as the character or part and merely offset to the position specified by distance / angle (the host has no blur-radius parameter either). Its size is always identical to the original, so at distance = 0 it overlaps exactly behind the main text and the shadow is not visible at all (it does not become visible through shrinkage or transparency).

FieldTypeUnitDescription
enabledboolean—Whether the Global shadow is enabled
distancenumberPercentage of the canvas's shorter side. 1.0 = 1% of the shorter side (px conversion: distance * min(width, height) / 100). Positive values move away in the angle direction. Maximum on write: 10.0Shadow distance
anglenumberdegreeShadow direction. 0 degrees points right, and positive (+) rotates right (clockwise) (90 degrees points straight down)
colorcolorRGBA 0–1Shadow color

Characters whose chars[index].shadow.use is false use shadow.color. For the inheritance order including parts, see "Inheritance Mechanism".

WARNING

Enabling the shadow increases drawing cost and reduces rendering performance. The impact is especially large at high resolutions or with complex text, so use it only when needed.

The gradient fills only areas where both the character and part fill.use values are false. An individual color with fill.use set to true takes precedence over the gradient and becomes a solid color. For the separation of stages between fill.use and opacity, see "Inheritance Mechanism".

Inheritance from the Character ​

A part's fill, stroke, and shadow are determined by their respective use values as follows.

Write-on ​

Visible elements are limited to those whose 1-based rank within the unit lies in [startLimit, endLimit].

text
startLimit = floor(write_on_start * N) + 1
endLimit   = ceil(write_on_end * N)

N is the number of characters when write_on_mode == "character" and the number of parts when it is "part".

How ranks are determined:

modeDefault RankWhen manual_order_enabledreorder_parts Only
characterCharacter index in layout order (1..N)Character-level manual reveal orderCharacter rank remains in layout order
partctx.parts[index].index (1..N)Manual reveal order of partsReveal order in stroke order

manual_order_text Syntax ​

Token Interpretation ​

Tokens are separated by commas or spaces. Invalid tokens are ignored, and if the same part is specified multiple times, only the first specification is used.

TokenMeaning
c<n> / C<n>1-based character n. Expands all parts of that character in the part order in effect at the time (reorder_parts true uses stroke order; false uses layout order)
p<n> / P<n>1-based global part n
<n>No prefix. Interpreted as a part index
<a>-<b>Inclusive range. Both endpoints must be of the same type (both characters or both parts). If only one endpoint has a prefix, the other inherits its type. Expands in ascending order

Examples: "3,1,2" (parts 3→1→2), "c1-c3" (characters 1–3), "p2-p5" (parts 2–5).

Effect on Ordering ​

Specified elements are moved to the front in the specified order. Unlisted parts are not hidden; they follow afterward while preserving their relative order from the base ordering.

The order is determined from the undeformed layout and the specification string; it is not recomputed each frame from spatial positions after animation. write_on_start/end determines the visible range, while manual order changes only the order of elements.

Editing path ​

path is a mutable object representing the part's drawing outline. You can clear or replace the original outline and add straight lines or Bézier curves. For details on the methods and coordinate system, see Drawing Path Editing API.
