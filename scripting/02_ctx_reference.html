このページの内容

対象APIレベル: 6

ctxは、Mug Typographyが各コールバックへ渡すコンテキストです。現在時刻、Canvas情報、 全体設定、生成された文字・パーツなど、そのフレームの処理に必要な情報が含まれます。

利用できるフィールドと書き込み権限はコールバックによって異なります。本書では、最初に コールバックごとの利用可否を一覧にしたあと、ctxのフィールドを順に説明します。 コールバックの実行順序と用途は コールバックの概要を参照してください。

1. ctxのフィールド一覧 ​

ctx直下のフィールド自体は読み取り専用で、別の値へ置き換えることはできません。 ただし、ctx.globalやctx.chars[index]などの内部には、コールバックに応じて変更できる フィールドがあります。○はそのコールバックで参照できることを表します。

1.1 ctx.time / ctx.frame / ctx.fps ​

現在の評価位置をクリップ先頭基準で表します。ctx.timeは秒、ctx.frameはフレーム単位です。 ctx.frameにはサブフレームが含まれる場合があるため、整数とは限りません。ctx.fpsは 1秒あたりのフレーム数です。

1.2 ctx.canvas ​

Canvasとプロジェクトの画素情報です。すべて読み取り専用です。

フィールド型単位内容
width / heightnumberpxCanvasの幅と高さ
aspect_rationumber—Canvasの幅を高さで割った値（width / height）
pixel_aspect_rationumber—ホストプロジェクトのピクセルアスペクト比

1.3 ctx.fonts ​

ホストが認識しているインストール済みフォントの名前を格納した、読み取り専用の1始まり配列です。 内容はホストUIのFontリストと同じで、OnPreLayoutでは要素をctx.global.font_nameへ 設定できます。

配列の要素や要素数は変更できません。

1.4 ctx.timeline ​

フィールド型単位内容
availableboolean—有限なクリップ範囲を取得できたか
start_frame / end_framenumberframe範囲の始端／終端（クリップローカル。始端は常に0）
duration_framesnumberframeend_frame - start_frame
duration_secondsnumbersecond秒に換算した長さ
progressnumber0–10–1にクランプされた現在位置

クリップ範囲 ​

クリップ範囲は、トリムや前後の引き伸ばしを含むタイムライン上の実範囲です。 ctx.time / ctx.frame / ctx.timelineには、クリップ先頭を0とした同じ時間軸の値が 渡されます。フィルタとして映像クリップに適用した場合も、そのクリップの範囲に追従します。

availableがfalseのときは他の値が0になるため、フォールバックを用意してください。

NOTE

ジェネレータ運用での前方引き伸ばしの制限: ジェネレータクリップ（入力未接続）の前方を タイムライン上で引き伸ばした場合、その区間はホストが先頭フレームの静止画として扱うため、 スクリプト時間は引き伸ばし境界まで進みません（イントロが先頭姿で静止して見えます）。 尺を変えたい場合は引き伸ばしではなくジェネレータクリップ自体の長さを変更してください。 フィルタ運用にはこの制限はありません。

時間軸の設計ルール（アンカー × 速度） ​

アニメーションの時間設計は「①どこに固定するか（アンカー）」と「②どの速さで進めるか（速度）」の 2軸で決めます。**速度の既定は実秒（ctx.time ベース）**で、クリップ長に比例させる progress を 使ってよいのは後述の「全体スパン型」だけです。

パターンアンカー書き方
イントロ（登場）クリップ先頭ctx.time をそのまま使う（実秒）。イントロ＋アウトロ一括なら mt.timeline.intro_outro_seconds(§10.9)
アウトロ（退場）クリップ終端mt.timeline.remaining(ctx)（終端までの残り実秒。§10.9）
タイプライター・stagger・ばね等クリップ先頭ctx.time（実秒。1文字あたり◯秒など物理速度で指定）
全体スパン型（尺いっぱいのドリフト・スイープ・リビール）クリップ全体progress（尺が伸びたら動きも伸びるのが期待動作）

トランジションを progress の割合で書くと、尺を伸ばしたときにフェードやタイピングが スローモーション化して破綻します。アウトロも本質は「終端に揃えること」であって速度を尺に 比例させることではないため、終端アンカーの実秒で書きます。

lua
-- NG: typing speed changes when the clip length changes
local visible = math.floor(mt.timeline.progress(ctx) * ctx.char_count)

-- OK: constant 0.08s per character regardless of clip length
local visible = math.floor(ctx.time / 0.08)

-- OK: outro fade over the last 0.5s, anchored to the clip end
local fade = mt.clamp(mt.timeline.remaining(ctx) / 0.5, 0.0, 1.0)

-- OK: 0.8s intro + 0.5s outro at fixed real-time speed
-- (compressed automatically only when the clip is shorter)
local intro, outro = mt.timeline.intro_outro_seconds(ctx, 0.8, 0.5)

1.5 ctx.font — 使用中フォントの寸法情報 ​

レイアウト生成後に確定した、使用中フォントのメトリクス（寸法情報）です。

フィールド型単位内容
ascentnumbercanvas 高さ比ベースラインから上方向のアセント
descentnumbercanvas 高さ比ベースラインから下方向のディセント（正値。下向きの量として表す）
line_heightnumbercanvas 高さ比行の高さ
units_per_emnumberフォント設計単位フォントの em 正方形の設計単位数

NOTE

画面上の最終サイズは scale 系フィールドの積で予測できます(2Dプリセット限定)。 フォントサイズはホストが内部で canvas.height に対する固定比率として計算しているため、 canvas解像度が変わっても同じ比率を保ちます。この基準サイズに character.scale × character.stretch_x/y・part.scale・ctx.global.scale × ctx.global.stretch_x/y を 掛け合わせたものが、2Dプリセットでは実際の画面上サイズと一致します(すべて乗算で 合成される変形だからです)。

3Dプリセットではこの積は近似にしかなりません。 カメラ投影が奥行き（z、 yaw/pitchによる見かけの奥行き変化、カメラの perspective / zoom を含む)に応じた 遠近除算を行うため、画面上サイズは奥行きに対して非線形に変化し、傾いた文字は 頂点ごとに歪みが生じて単一の倍率では表せません。ctx.fontとcharacter.geometry は投影前の値であり、投影後の画面上サイズはOnLayoutから取得できません。

1.6 ctx.text / ctx.char_count / ctx.part_count ​

ctx.textは廃止予定です。現在のテキストを参照するときはctx.global.textを使い、 書き換えるときはOnPreLayoutでctx.global.textへ代入してください。

ctx.char_countとctx.part_countは、それぞれレイアウト生成後の有効な文字数とパーツ数を 表します。テキストやフォントを変更すると、シェイプ結果に応じて値も変わります。

instance_seedの用途 ​

instance_seedをmt.randomのseedに使うと、同じスクリプトでもインスタンスごとに 異なる乱数列になります。

ctx.global.margins ​

インデックスと計算 ​

marginsは、レイアウト順の文字番号をキーとする1始まりの配列です。この番号は、 あとでctx.charsに付くindexと同じです。margins[i]はi番目の文字の後ろの送りへ、 trackingと合わせてem単位で加算されます。

text
(margins[i] + tracking) * designUnitsPerEm
配列形式 ​

1から#marginsまで穴のない数値キー配列にしてください。非整数キー、文字列キー、 途中の穴、number以外の要素はエラーになります。

既定の要素数はctx.meta.limits.max_charactersです。テーブル全体を代入する場合は、 既定の要素数より短い、穴のない配列も使用できます。文字数を超えた要素はエラーにならず、 単に使用されません。

文字数 ​

OnPreLayoutではctx.char_countが未定義です。utf8.len(ctx.global.text)で得られるのは UTF-8コードポイント数であり、結合文字、合字、書記素クラスタなどにより、シェイプ後の 文字数と一致しない場合があります。正確な個数が必要な処理はOnLayoutで行ってください。

サブオブジェクトのマージ ​

ctx.global.shadow = { enabled = true, distance = 8.0 }のようにテーブル全体を代入すると、 フィールドごとにマージされます。省略したフィールドは現在値を維持します。

ctx.global.fill ​

NOTE

color型

colorはr（赤）、g（緑）、b（青）、a（アルファ）を持つテーブルです。 各フィールドは0–1のnumberで、a = 0は完全な透明、a = 1は完全な不透明を表します。

フィールドへ直接代入できるほか、テーブル全体を代入するときは変更するフィールドだけを 記載できます。省略したフィールドは現在値を維持します。

lua
ctx.global.fill.color.r = 1.0
ctx.global.fill.color = { a = 0.5 }

r / g / b / a以外のフィールドや、number以外の値はエラーになります。

フィールド型単位内容
colorcolorRGBA 0–1全体の塗り色。グラデーションの始端色も兼ねます
transparentboolean—trueにすると、ストロークや効果を残して塗りを非表示にします

chars[index].fill.useがfalseの文字にはfill.colorが使われます。 パーツまで含めた継承順は「継承の仕組み」を 参照してください。

ctx.global.shadow ​

NOTE

このシャドウにぼかし(blur/softness)は一切ありません。文字・パーツと同じ形状を distance/angle の位置へオフセットしただけの、輪郭が鮮明な単色コピーです (ぼかし半径のパラメータはホスト側にも存在しません)。サイズは本体と常に等倍のため、 distance = 0 では本体テキストの真後ろに完全一致で重なり、見た目にはシャドウが 全く見えません(縮小されて透けて見える、といった挙動にはなりません)。

フィールド型単位内容
enabledboolean—全体シャドウの有効状態
distancenumbercanvas 短辺に対する百分率。1.0 = 短辺の 1%（px 換算: distance * min(width, height) / 100）。正で angle 方向へ遠ざかる。書き込み時の上限は10.0シャドウ距離
anglenumberdegreeシャドウ方向。0度で右方向、正（+）で右回り（時計回り）に回転（90度で真下方向）
colorcolorRGBA 0–1シャドウ色

chars[index].shadow.useがfalseの文字にはshadow.colorが使われます。 パーツまで含めた継承順は「継承の仕組み」を 参照してください。

WARNING

シャドウを有効にすると描画負荷が増え、レンダリング性能が低下します。 特に高解像度や複雑なテキストでは影響が大きくなるため、必要な場合だけ使用してください。

グラデーションが塗るのは、文字・パーツのfill.useがどちらもfalseの部分だけです。 fill.useがtrueの個別色はグラデーションより優先され、単色になります。 fill.useとopacityの段階分けは 「継承の仕組み」を参照してください。

1.9 ctx.camera ​

3Dプリセットのカメラです。2Dプリセットでも代入はエラーになりませんが、描画に反映されるのは 3Dプリセットだけです。

フィールド型単位内容
target_x / target_ynumbercanvas正規化座標カメラ注視点。Xは右、Yは上が正です。注視点が動くとオブジェクトは逆方向に動いて見えます
yaw / pitchnumberdegreeカメラの旋回。yawは正（+）でカメラが右に回り込み、pitchは正（+）で上に回り込む（見下ろす）
perspectivenumber—カメラ距離／遠近感を表す強度。内部でカメラ距離distancePx = f(perspective) * canvas.heightに写像されます（fは強度から距離係数への単調写像で、大きいほどカメラが近づき遠近が強くなります）
zoomnumber倍率投影拡大率。書き込み時に最小0.001へクランプされます
lens_shift_x / lens_shift_ynumbercanvas比率主点移動。lens_shift_xの正（+）で全体が右、lens_shift_yの正（+）で全体が上にシフト

1.10 ctx.chars[index] ​

ctx.charsはLua標準どおり1始まりの配列です。テキストやフォントが変わると、 文字数と各要素のindexも変わります。

fill / stroke / shadowのuseがfalseの場合は非表示になるのではなく、 グローバル値を継承します。詳しくは 「継承の仕組み」を参照してください。

フィールド型単位内容

textstring—この文字クラスタの元テキスト。読み取り専用
part_start / part_countinteger—所有パーツの先頭グローバルindex（1始まり）と個数。読み取り専用
line_indexinteger—属する行の1始まりindex。読み取り専用
geometrytable—変形前の配置情報（下記）。読み取り専用
offset_x / offset_ynumbercanvas正規化変位文字の移動量。0.5で変位量0になり、大きいほど右／上へ移動します
pivot_x / pivot_ynumbercanvas正規化変位文字変形の支点。0.5で自然中心になり、大きいほど右／上へ移動します
scalenumber倍率均等スケール。書き込み時に最小0.001へクランプされます
stretch_x / stretch_ynumber倍率非均等スケール。scaleと異なり正の下限はなく、0や負値も受理されます

ctx.partsはLua標準どおり1始まりの配列です。indexは文字ごとの番号ではなく、 フレーム全体を通したパーツ番号です。テキストやフォントが変わると、パーツ数と各要素の indexも変わります。

フィールド型単位内容

文字からの継承 ​

パーツの塗り・ストローク・シャドウは、それぞれのuseによって次のように決まります。

パーツの設定use = falseuse = true

インスペクタにない個別設定 ​

パーツのstrokeとshadowにはインスペクタ上のパラメータがなく、初期状態は 未使用／既定値です。スクリプトでuseをtrueにすると、設定した個別値が優先されます。

yaw / pitchもインスペクタにはなく、初期値は0です。所有文字の回転とは独立しており、 文字の回転空間内で追加の回転として適用されます。

Write-on ​

表示対象は、単位ごとの1始まりの順位が[startLimit, endLimit]に入る要素に限られます。

text
startLimit = floor(write_on_start * N) + 1
endLimit   = ceil(write_on_end * N)

Nはwrite_on_mode == "character"のとき文字数、"part"のときパーツ数です。

順位の取り方:

mode既定の順位manual_order_enabled 時reorder_parts のみ
characterレイアウト順の文字 index（1..N）文字レベルの manual reveal 順文字順位はレイアウト順のまま
partctx.parts[index].index（1..N）パーツの manual reveal 順stroke order の reveal 順

manual_order_text 構文 ​

トークンの解釈 ​

トークンはカンマまたは空白で区切ります。無効なトークンは無視され、同じパーツを 複数回指定した場合は最初の指定だけが採用されます。

トークン意味
c<n> / C<n>1 始まり文字 n。その文字の全パーツを、当時のパーツ順（reorder_parts が true なら stroke order、false ならレイアウト順）で展開
p<n> / P<n>1 始まりグローバルパーツ n
<n>プレフィックス無し。パーツ index として解釈
<a>-<b>両端を含む範囲。両端は同じ種別（文字同士またはパーツ同士）。片方だけプレフィックスがある場合は他方に種別を継承。展開は昇順

例: "3,1,2"（パーツ 3→1→2）、"c1-c3"（文字 1〜3）、"p2-p5"（パーツ 2〜5）。

順序への反映 ​

指定された要素は指定順で先頭へ移動します。未指定パーツは非表示にならず、 基準順序での相対順を保って後ろへ続きます。

順序は未変形のレイアウトと指定文字列から決まり、アニメーション後の空間位置から フレームごとに再計算されません。write_on_start/endは表示範囲を決め、 manual orderは要素の順序だけを変更します。

1.14 ctx.paths ​

ctx.pathsは対象を遅延取得するため、取得しなかったパーツのパスはLua側へコピーされません。

select(selector)の選択書式 ​

cは文字番号、pは通しパーツ番号、!は除外を表します。カンマで複数の条件を 指定でき、c3-5やp8-10のような範囲にも対応します。

lua
local parts = ctx.paths:select("c1, p8-10, !p9")

同じパーツを複数回取得した場合、同一フレーム内では同じ可変オブジェクトが返されます。
